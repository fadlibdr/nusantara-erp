## Open questions

**OQ-1 — Scope of UX-C, UX-D, UX-E3 against the earlier UI campaign.** *(UX-C followed the proposal: current code is the baseline; each task's Deviations line names what was skipped because it already existed.)* The packages are specified against a `main` that predates UI-0 to UI-7. E3.1 and E3.2 (extract the builder, add the `f/` route with guard) are already shipped for every form with lines, so "modal behaviour byte-for-byte unchanged" has nothing to protect for those forms. What remains of E3 is smaller than written: Simpan & ajukan, the error summary, the section nav. I have not started any of it. Proposal: treat the current code as the baseline for every package, build only what the grep table above lists as missing, and say so in each package's Deviations line. This does not need an owner decision unless you want the earlier campaign's choices reversed. Also open: `origin/main` lacks the 45 commits, so pushing needs the owner to reconcile the divergence.

**OQ-2 — S3 and S4 target a dialog that no longer exists.** *(Done as UX-C.0, `81bcfe0`; both green since.)* The E-6 gate "S3, S4 equal baseline" cannot be evaluated while both are red. Updating them to the page is allowed by ground rule 7 (the structure changed on purpose) and weakens nothing, but it is a harness change and UX-0 is measurements only. Proposal: do it as the first commit of UX-C, derived from `ux0-adapt-s3-s4.py`, before any gate that names them.

**OQ-3 — Smallest font bound.** ERRATA §4 says ≥ 11 px on the PO list. Main reads 10 px, from one keycap that UI-4 sets deliberately. The handoff's top bar keeps a `Ctrl K` keycap, so UX-D will hit this again. Proposal: gate on "no prose under 11 px, keycap exempt", matching S8's existing floor of 10 px. Needs your confirmation, because it relaxes a bound ERRATA states.

**OQ-5 — `--primary` and `--accent-1` have parted (UX-C.1).** README C1 changes `--primary` and freezes the accent and chart palettes, so Proyek's accent (`#1a56db`) and the primary button (`#2b4fc8`) are now two close blues. Nothing in tests or the harness pins the identity; CONVENTIONS §12 and the token comments record it. If you would rather keep them identical, the choice is between re-deriving slot 1 (and its ΔE matrix) from the new primary, or keeping the old primary — both are owner calls on a palette the handoff declared frozen. Built as written until told otherwise.

**OQ-6 — Typed search hits need fields `core/search` does not send (UX-D.7).** README Phase D asks for "kind — party title, sub (project · amount · submitter), status badge". `GlobalSearchService` returns `id`, `code`, `title` and `link` per hit; party, project, amount, submitter and status are not there. Rendering them means adding fields to the response, which ground rule 2 forbids ("no change to … API contracts"). Built: module icon, mono code, title or kind. Owner call: allow an additive field set on `core/search` (with its own Feature test), or keep the hits as they are.

**OQ-7 — S28 `two_documents_were_actually_picked` is red on a fresh seed, before and after UX-D.** The delegate's queue holds one document (`CTI/2026/VIII/0002`), and the check expects exactly two. Measured on the base SPA (`4d7cc1c`, same backend, same fresh seed) with the base harness: the same single failure. Not caused by this redesign; not investigated further. Every other S28 check is green, including the delegation banner and "Setujui terpilih".

**OQ-4 — Which sidebar number is the bound.** S5 reports raw scroll height (2.6) and content height (0.93). ERRATA's 0.7 was a content figure. Proposal: gate UX-D on content height ≤ 2.0 viewports, which holds with wide margin.
